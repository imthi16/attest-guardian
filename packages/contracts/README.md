# Contracts

`openapi.json` is the API's own description of itself, generated by `apps/api/app/contracts.py` via
`make contracts` and committed deliberately.

It exists because the web app is a separate program that has to agree with the API about every
response body, and it agrees by hand — `apps/web/lib/contracts.ts` restates each shape as a Zod
schema. That is the right trade (no generator in the browser bundle, and the client can be stricter
than the server), but **a mirror that drifts is worse than none**: it either rejects a valid
response, so the page reports a transport failure for data that arrived intact, or accepts a field
that never comes and renders nothing. That failure has already happened once, and a reviewer caught
it rather than a test.

So both sides are pinned to this file:

| Test | Fails when |
| --- | --- |
| `apps/api/tests/test_contracts.py` | The committed file no longer matches the application |
| `apps/web/lib/contracts.drift.test.ts` | A Zod schema has a field the API does not return, or lacks one it does |
| `apps/web/lib/attest-api.drift.test.ts` | The app requests a path the API does not serve |
| `apps/api/tests/test_documentation.py` | `docs/API.md` documents a path the API does not serve, or omits one it does |

Regenerate deliberately and **read the diff**. It is the contract, and both suites are about to be
checked against it.

Contracts must preserve structured citations, provenance, stable error codes, and authorization
context. Generated clients, when they exist, belong here too.
